# 部署与验收

本项目继续提供单条链接手动解析；公开批量解析接口未提供。网页输入方式不能阻止脚本调用 HTTP API，因此保留服务端安全准入。产品宣传文案按运营者要求保持原样，本文件记录实际运行限制。

## 本次已实现的运行边界

- 解析：同一每日 IP 摘要 5 次/小时、20 次/天；同一摘要最多 1 个在途解析，单实例共享数据库最多 2 个。请求体 16 KiB，字段 4096 字符，解析 60 秒超时。
- 媒体：同一摘要 600 次/小时、2000 次/天，同一 token 60 次/小时、120 次/天；全局最多 6 个、同一摘要最多 4 个传输。媒体传输最长 180 秒。
- 运维验证令牌只用于授权样本 CLI，独立限制 100 次/小时、200 次/天，也受全局并发限制。没有公开验证码或声称绝对识别“手动用户”。
- 限流、并发租约、代理预算均由 SQLite 事务处理。临时媒体 token 在进程内，部署只运行一个应用实例；重启会使旧 token 失效，多实例负载均衡不在本次部署范围内。
- 预览和下载统一计量。先预留，再结算；余额不足时降低可传输字节上限。无长度响应逐块限制预算。崩溃遗留的预留额度在过期后按最大值计费，避免重新释放造成超支。
- 成本为保守估算，不等同云厂商账单；实际带宽单价、税费、平台页面加载和浏览器出口成本需单独纳入运营预算。
- 浏览器所有 HTTP(S) 请求及重定向都由固定 DNS 地址的服务端请求完成，校验失败即拒绝。WebSocket、服务工作线程、子框架导航和无关图片/媒体/字体加载被拒绝；每次渲染最多 300 个准入资源请求、32 MiB 响应和 8 个在途子请求。开启 Chromium 沙箱。资源等待空闲容量，失败请求只按实际读取的字节计量；匿名 Cookie 仅存在于当次隔离浏览器上下文中。
- 临时结果有容量上限及定时清理；已结案投诉 180 天后清空联系方式和说明，帖子屏蔽标识保留。聚合指标保留 30 天，业务诊断只写固定错误类别与请求编号，按日文件保留最近 7 个日期、每日大小受限。

## 正式配置

1. 使用 Node.js 24，在项目目录复制 `.env.example`，执行 `npm run setup:admin -- --write-env`。一次性凭据移入密码管理器；原文件不提交，也不放入部署镜像。
   密码及恢复码哈希使用 `base64:` 包装，防止 Next.js 和 Compose 将 scrypt 哈希中的 `$` 当作环境变量展开；包装不是加密，内容仍是加盐哈希。
2. 设置 `APP_ORIGIN=https://你的实际域名`，不带尾斜杠；设置真实 `COPYRIGHT_EMAIL` 和 `TRUST_PROXY_HEADERS=true`。独立部署配置中保留随机密钥、管理员密码哈希、TOTP、恢复码和备份密钥。
3. 在服务器安装 TLS 证书，将 `deploy/nginx.conf.example` 的域名和路径替换后启用。代理必须覆盖 `X-Real-IP` 和其他转发头；应用端口只能由该代理访问。不要改为公开绑定 3000，也不要直接信任客户端提供的 IP 头。
4. 执行 `npm run test:container`，验证镜像没有 `.env`、无权限容器中的 Chromium 沙箱能启动、生产健康接口工作。此测试使用独立 `linkkeep-smoke` Compose 项目和随机测试配置，不会使用正式管理员密钥。
5. 正式目录执行 `docker compose build`、`docker compose up -d`。检查健康状态，验证实际投诉邮箱能收信，并手工走一遍投诉、登录、CSRF 和帖子停止解析流程。

若宿主机不支持受约束的用户命名空间导致 Chromium 沙箱检查失败，应修复宿主机与容器配置；不要以关闭沙箱或添加 SYS_ADMIN 作为上线兜底。seccomp 配置采用 [Playwright 官方方案](https://playwright.dev/docs/docker#recommended-docker-configuration)，具体来源见 `deploy/seccomp-source.md`。

## 调度、监控和备份

`deploy/linkkeep-maintenance.service` 和 `.timer` 每日执行清理及加密备份；`deploy/linkkeep-health.service` 和 `.timer` 每 5 分钟检查健康、近期失败率、预算达到 80%、平台自动熔断和备份新鲜度。根据正式路径替换 `/opt/linkkeep`，复制到服务器 systemd 目录后启用这两个 timer。成功检查保持静默，异常返回非零；通过正式监控系统收集服务失败事件。此仓库没有启用邮件或聊天通知，也没有在本机安装这些服务。

运行中的应用也会每小时清理到期数据库资料和诊断日志；每日备份调度仍需在宿主机启用。容器 stdout/stderr 日志有大小限制；宿主机日志平台应另设 7 天留存，避免长期保留框架诊断输出。Nginx 示例关闭请求访问日志，业务日志不包含完整分享输入、媒体 URL 或原始 IP。

执行 `npm run test:backup` 可以在独立测试数据库验证加密恢复、7 份保留、结案个人资料脱敏、篡改和错误密钥拒绝，以及不覆盖已有数据库。实际服务首次部署还需从正式加密备份恢复到隔离目录，确认投诉和帖子屏蔽数据。加密快照需同步到受控异地存储；目的地由运营者确定，本次没有创建外部存储或上传数据。

后台 `/api/admin/operations` 的认证响应包含近期指标。解析记录尝试、成功、失败；默认代理下载记录尝试、首个媒体字节和失败。指标用于健康观察，授权固定/动态样本验收仍以独立报告为准。

## 放行和回滚

1. 执行单元测试、类型检查、Lint、备份恢复、下载验证器检查、生产构建、生产 E2E、依赖审计和容器检查。CI 工作流包含上述检查；尚未推送或实际运行远端 CI。
2. 使用抖音和小红书各 10 条授权公开固定样本验收；独立动态清单达到 90% 解析、95% 下载启动。默认代理需实际读到匹配签名的媒体字节，307 重定向不能算下载成功。再人工验收直连、预览、ZIP、过期和停止解析。
3. 在部署网络及真实 iOS Safari、Android Chrome/Edge、桌面 Chrome/Edge/Safari 验证。Playwright 的 iPhone 配置是 WebKit 模拟，不能替代真实 iPhone 验收。
4. 先小流量试运行，检查资源占用、成功率、实际账单和投诉路径，再决定开放范围。
5. 发布前保存当前镜像标签和加密数据库快照。回滚到前一镜像前，确认其支持当前 SQLite 表结构；本次变更新增表及清空到期个人资料，回滚不能恢复已清理资料。必要时关闭流量入口，在隔离目录恢复快照并核验后切换数据路径。不得恢复被投诉的媒体或删除帖子屏蔽记录来提高成功率。
