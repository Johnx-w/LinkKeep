# 本地解析回归修复（2026-10-03）

运营者使用 `http://localhost:3000/zh`，本机 `.env` 的 `APP_ORIGIN` 为 `http://127.0.0.1:3000`。新增的同源校验只接受精确匹配，因此从 localhost 页面发出的解析请求在访问来源平台之前返回 `403 INVALID_ORIGIN`。前端没有对应错误映射，错误地显示成“暂时无法解析该链接”和“确认内容公开且无需登录”。

修复前实测：同一个本机接口，127.0.0.1 来源的无链接输入得到 `400 NO_LINK`，localhost 来源得到 `403 INVALID_ORIGIN`。运营者随后确认自己打开的是 localhost 地址。此前提供的旧请求编号没有详细失败日志，无法直接还原它的响应码；上述结果证明了可稳定复现的本机误拒绝。

## 已修复

- 开发模式兼容同协议、同端口的 localhost、127.0.0.1 和 IPv6 回环入口。其他端口、伪装域名、跨站请求和缺失来源仍被拒绝；生产模式仍匹配正式配置。
- 分别显示地址配置错误、输入没有链接和代理配置错误，通用失败提示不再推断内容是否公开。产品宣传文案没有修改。
- 开发模式解析不按小时或每日次数限流，不因连续平台失败自动熔断；开发初始化恢复以前自动熔断的平台，保留环境变量及后台手动停用。
- 开发热更新重新初始化解析服务，避免进程全局缓存继续运行修改前的浏览器加载和运维逻辑。生产服务保留原缓存行为。

这里只调整本机调试体验，并未实现对来源平台账号权限或登录访问控制的绕过。来源实际返回媒体时按现有适配器解析；两条提供的样本都能读取。

## 验证

93 项单元测试、TypeScript 和 ESLint 通过，包含开发/生产来源策略、次数限制、自动熔断及热更新回归用例。

从运营者使用的 localhost 地址，抖音完整分享文本解析出 1 个 1440×2560 视频；小红书完整分享文本解析出 3 张 1440×2560 图片。代理下载实际读取文件字节并识别为 MP4 和 HEIC，均返回 HTTP 200；未把 307 重定向当作下载通过。检查报告位于忽略提交的 `artifacts/demo/localhost-regression-verification.json`，不包含管理员密钥和媒体访问令牌。

Edge 已运行，控制插件及其通信配置检查通过，但浏览器控制通信请求失败。本次通过正在运行的本机 API 完成实际验证，没有在 Edge 中自动点击。刷新本地页面后再使用原分享链接即可。
